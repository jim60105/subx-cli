**What the gate actually verifies for a documentation change.** The four steps are the series' standard gate and are reproduced unchanged, but only two of them carry weight here and their meaning shifts:

- **10.1** is near-vacuous for Markdown edits and non-vacuous for tasks 8.1 and 8.2, which touch `subx-core/Cargo.toml` and `subx-cli/src/lib.rs`. `cargo fmt` reaches workspace members already; `clippy` reaches both crates only because C1 added `--workspace` to the script — the bare command in this step still covers the root package alone, which is why 10.3 is the authority and not this step.
- **10.2** is the weakest step of the four and is retained for form. No test in either crate asserts anything about a Markdown file, and the filter is deliberately narrow — `test(version)` and `test(core_version)` cover B1's `CORE_VERSION` major-component assertion, which is the one test that fails if task 8.1's manifest edit is malformed enough to break resolution.
- **10.3** is the real gate, and it is doing something new: after task 4, `scripts/quality_check.sh` contains the governance check, so a green run now additionally asserts that the two `openspec/` trees are disjoint outside the recorded split set, that no split lost a half, and that the two `AGENTS.md` files' shared regions are byte-identical. A red verdict from this step is now as likely to be a documentation defect as a code defect. It also runs the `--workspace` doc build (`quality_check.sh:253` after C1), which is where an illegal intra-doc link across the crate boundary becomes a failure.
- **10.4** is the step with the most residual power for a documentation change, and it is genuinely load-bearing: `broken_intra_doc_links = "deny"` means every rustdoc path edited in tasks 8.2 and 8.3 is compiled, and a doc example that names a module that moved repositories fails here rather than shipping. Note that it does **not** cover the dead-href case Decision 4 Rule 3 describes — that one is invisible to every step of this gate, which is why task 8.4 inspects the generated output by hand and task 8.5 builds core standalone.
