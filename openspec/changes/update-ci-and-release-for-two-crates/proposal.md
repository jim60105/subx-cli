## Why

Seven changes have landed. A0 pruned five phantom dependencies. A1 and A2 cut the fourteen `core`/`services` → `cli` edges. B1 created `subx-core`, mounted it as a submodule at `subx-core/`, made `subx-cli` the Cargo workspace root and added `submodules: recursive` to all seven `actions/checkout` steps. B2 moved 36,687 LOC of library code across the boundary and split the manifests. B3 split the test suite 40/80 and built the `test-support` mechanism. B4 revived eight never-compiled test files, converted 26 runtime binary lookups to `env!("CARGO_BIN_EXE_subx-cli")`, and **measured** the per-crate coverage numbers.

Everything in that list stopped at the same line. B1 wrote it down in as many words — its CI contract was "seven checkout steps and nothing else" — and B2, B3 and B4 each restated the division in their own Non-Goals. The result is a repository that is architecturally two crates in two repositories and operationally still one crate in one repository:

**1. The release pipeline cannot publish this project at all.** `release.yml:196` is a single `cargo publish --token …`. `subx-cli` now declares `subx-core = { path = "subx-core", version = "1.0" }`, and `cargo package` strips the `path`, leaving a registry requirement for a crate that has never been uploaded. The first `v*` tag after the split fails in `publish-crates`, after `create-release` has already created a public GitHub Release and after the five-target `build` matrix has already attached its artifacts. There is no ordering, no dry-run gate, and no version floor for a Cargo new enough to do the ordering itself.

**2. `cargo publish` will refuse before it even gets there, and the reason will not be obvious.** Since Cargo 1.39, `cargo package` and `cargo publish` walk submodules recursively looking for uncommitted changes, and a moved-but-uncommitted gitlink makes the *parent* dirty. The failure names a dirty working directory, not a submodule pointer, and the one flag that silences it — `--allow-dirty` — stamps `"dirty": true` into `.cargo_vcs_info.json` inside the published `.crate`, permanently, for everyone who inspects the archive.

**3. The quality gate has a 43-file hole in it.** `default-members` is unset, so the default member set is the root package. `scripts/quality_check.sh:328,331` run `cargo nextest run` without `--workspace`; after B3's move that silently skips all 43 `subx-core` test files, and the script exits green. `scripts/quality_check.sh:227,237` do the same for `cargo check` and `cargo clippy`, as does `build-test-audit-coverage.yml:61`. AGENTS.md calls `scripts/quality_check.sh` "the single source of truth for quality validation"; today that sentence is false for a third of the test suite.

**4. Coverage is one number over two very different denominators, and its exclusion list is a file nothing reads.** B4 measured each crate and derived a floor for each; the scripts, the two CI environment blocks and the report invocation know nothing about them. Meanwhile `.llvm-cov.toml` — present in both repositories since B1 copied it "for parity" — is referenced by no script, no workflow and no manifest in either repository. Its `exclude-from-report = ["benches/*", "tests/*", "src/main.rs"]` has never been in force. B3 found it, B4 confirmed it and specified the replacement, and both handed the decision here.

**5. `subx-core` has no CI.** A commit pushed to `jim60105/subx-core` is compiled by nothing until somebody moves the pointer in `subx-cli`. The first signal that core is broken arrives inside a `subx-cli` pull request, attributed to the wrong repository, after the fact.

**6. The pointer can silently be wrong.** B1 installed `.gitmodules`' `branch = main` and documented `git config submodule.recurse true`, and named the two mitigations it deliberately left here: a Dependabot `gitsubmodules` entry (the repository has no `.github/dependabot.yml` at all) and a CI assertion that the pinned core commit's version satisfies the caret requirement in `subx-cli`'s dependency line. Nothing in Cargo checks that agreement — inside the workspace `path` wins outright and the `version` key is never consulted for resolution.

**7. Two smaller defects were queued behind all of the above.** `[profile.default.junit] path = "target/nextest/junit.xml"` (`.config/nextest.toml:55-57`) resolves relative to `target/nextest/default/`, so it writes to `target/nextest/default/target/nextest/junit.xml`; `.gitignore:19-20` carries two competing patterns as the fossil record of that confusion. And `hashFiles('**/Cargo.lock')` in four cache steps now globs `subx-core/Cargo.lock` as well as the workspace lockfile — a file that is inert inside the workspace and whose churn invalidates caches for no reason.

This is series change **C1**. It is the change that makes the operational half of the project match the structural half, and it performs the release event that ships the split: **`subx-cli` 2.0.0** and **`subx-core` 1.0.0**, per SDR D6.

## What Changes

**1. The publish job becomes an ordered, gated, two-crate flow.** `publish-crates` gains, in order: a Cargo version floor assertion (`cargo publish --workspace` needs Cargo ≥ 1.90; `dtolnay/rust-toolchain@stable` satisfies it today but does not *guarantee* it, so the job asserts rather than assumes); a submodule cleanliness precondition that fails on a `+`/`-`/`U` prefix from `git submodule status --recursive` or on any output from `git -C subx-core status --porcelain`; a sparse-index probe that determines which members actually need publishing at this tag; `cargo publish --workspace --dry-run`; and then the real publish, as `--workspace` or `--workspace --exclude subx-core` depending on the probe. `--allow-dirty` appears nowhere, and a grep assertion in the same job keeps it that way. The two-stage fallback (`cargo publish -p subx-core` then `-p subx-cli`, leaning on Cargo's built-in index-propagation wait) is documented in `design.md` as the recovery path, not wired in as the default.

**2. `subx-cli` moves to 2.0.0 and `subx-core` is released at 1.0.0.** `Cargo.toml:8` becomes `version = "2.0.0"`; `Cargo.lock` is regenerated by Cargo, never hand-edited. `CHANGELOG.md` gains a `## [2.0.0] - <date>` section in the exact shape `release.yml:29`'s `awk "/^## \[$VERSION_NUM\]/…"` parses, with `### Added`, `### Changed`, `### Removed`, `### Migration` and `### Documentation`. `subx-core` keeps `version = "1.0.0"`, keeps its independent version line, and `subx-cli`'s dependency keeps the caret `version = "1.0"`. `subx-core/CHANGELOG.md` is created with its own `## [1.0.0]` entry, because a crate cannot be published to crates.io at 1.0.0 with no release record — the prose rewrite across both repositories remains C3's.

**3. The quality scripts become workspace-aware, and `subx-core` gets a thin script of its own rather than a port.** `scripts/quality_check.sh` and `scripts/quality_check.ps1` pass `--workspace` on `cargo check`, `cargo clippy` and both `cargo nextest run` invocations. `build-test-audit-coverage.yml:61,133,139` gain the same flag. `default-members = [".", "subx-core"]` is *additionally* set in the workspace table, so a contributor typing the bare `cargo nextest run` that AGENTS.md instructs also gets both crates — the manifest key protects the human, the explicit flag protects the gate. The multi-package `--features` interaction that would have made this unsafe was verified not to exist under `resolver = "3"` (`design.md` Decision 5).

**4. Coverage is wired end to end with B4's numbers.** One instrumented `cargo llvm-cov nextest --profile <p> --workspace --no-report` run, unchanged. Both `cargo llvm-cov report` invocations — the `--lcov` one and the `--json --summary-only` one — gain the identical `--ignore-filename-regex '(^|/)(tests|benches)/|(^|/)src/main\.rs$|(^|/)src/test_support/'` that B4 specified. `scripts/check_coverage.sh` and `scripts/check_coverage.ps1` partition `.data[0].files[]` by whether the path contains `/subx-core/src/`, compute a percentage per crate, and gate each against its own floor: `COVERAGE_THRESHOLD` (workspace, 75, unchanged and the gate that may not regress), `COVERAGE_THRESHOLD_CORE` and `COVERAGE_THRESHOLD_CLI`, whose values are B4's recorded `floor(measured − 3)` clamped to its 75 / 65 minima. `build-test-audit-coverage.yml:186-198` sets all three on both the Linux and Windows steps.

**5. `.llvm-cov.toml` is deleted from both repositories.** It is not configuration that stopped working; it is a file whose keys no tool in this project has ever read. Keeping it while the real exclusions live in a command-line flag is precisely the state B4's spec forbids — an inert file being mistaken for the mechanism. The exclusion set now has one expression per invocation site and a normative value. This drops a bullet from B1's *Configuration Duplicated into the Core Repository* requirement, which is why `crate-topology` appears below.

**6. `subx-core` gets its own CI.** `subx-core/.github/workflows/build-test-audit-coverage.yml`, deliberately named after the parent's so the two stay diffable: a `test` matrix across `ubuntu-latest`, `windows-latest` and `macos-latest` (core is where every platform-sensitive path lives — encoding detection, path handling, audio decoding, archive extraction; dropping a platform would move its first signal to a pointer bump, which is the failure this workflow exists to prevent); a `security` job auditing core's **own** lockfile, which the parent's workspace-union audit does not cover; and a `coverage` job that measures and uploads but does **not** gate, because a standalone core run has a strictly smaller numerator than the workspace-attributed figure B4's floor was derived from. No `build` matrix, no release job, no installer, no `publish-crates` — `subx-core` is published by the parent's `cargo publish --workspace`, and `design.md` Decision 9 states what that couples and what it does not.

**7. Pointer staleness gets three checks with three distinct failure modes.** A new `submodule-pointer` job in the parent's workflow asserts (a) that the pinned `subx-core` version satisfies the caret requirement read from `cargo metadata --no-deps`, (b) that the pinned commit is reachable from `origin/main` — soft on pull requests, where the core commit may legitimately still be in review, hard on `master` pushes and inside `publish-crates` — and (c) that `.gitmodules` still records `branch = main`. `.github/dependabot.yml` is created with a single `package-ecosystem: gitsubmodules` entry; `cargo` and `github-actions` ecosystems are deliberately not added here.

**8. The nextest junit path defect is repaired in both repositories.** `[profile.default.junit] path` becomes `"junit.xml"`, so the default profile writes `target/nextest/default/junit.xml`; the table moves from the bottom of the file to directly under `[profile.default]`, since its distance from its own profile is why the defect went unnoticed. `[profile.ci.junit]` is left exactly as it is — B1 Decision 5a established that it already resolves to the `target/nextest/ci/junit.xml` the two Codecov steps upload, and a task verifies that empirically rather than by reading. `.gitignore:19-20`'s two competing patterns collapse to one. The Chinese comments in `subx-cli/.config/nextest.toml` are rewritten in English, closing B1 Decision 5's deliberate divergence.

**9. Cache keys and the audit surface are corrected for two lockfiles.** The four `hashFiles('**/Cargo.lock')` keys narrow to `hashFiles('Cargo.lock')`: the workspace build resolves against the root lockfile alone, and `subx-core/Cargo.lock` is inert inside the workspace (B1 Decision 5b). The `security` job keeps B1's `submodules: recursive` and gains a spec requirement stating *why* — the audited graph is the workspace union, and any Cargo command that loads the workspace manifest fails without the member present.

The release matrix stays at **five** targets. No musl entry is added, no asset name changes, `scripts/install.sh` is not touched, and the binary's observable behaviour is identical. AGENTS.md's stale "7 targets" claim (`:396-403`) is left to C3, as B1's task 8.3 already arranged; a task in this change asserts the matrix is unchanged so the existing `release-distribution` scenarios stay satisfied.

## Capabilities

### New Capabilities

_None._ The two-repository CI contract does not need one. Its three parts already have homes: the submodule-checkout and per-repository-configuration rules are `crate-topology`'s (B1), the coverage-tooling contract is `cross-crate-testing`'s (B4, which explicitly says the tooling "SHALL be … implemented by the change that owns the CI and release pipeline"), and the publish flow is `release-distribution`'s. Minting a fourth capability would split the submodule contract across two documents whose requirements would then have to be read together to be understood. `design.md` Decision 14 records the reasoning.

### Modified Capabilities

- `release-distribution`: **ADDS** two requirements — *Two-Crate Publication Order and Preconditions*, covering the ordered `--workspace` publish, the Cargo ≥ 1.90 floor and its CI assertion, the committed-and-clean submodule precondition, the `--allow-dirty` prohibition, the dry-run gate, member selection at a tag, and the recovery procedure when one of two uploads fails after the other has succeeded; and *Release Version Bump and Changelog Header*, fixing the `subx-cli` 2.0.0 / `subx-core` 1.0.0 relationship, the independent version lines, and the exact `## [VERSION]` header shape the release workflow's `awk` extraction depends on. **MODIFIES** *archive-rar feature parity across Linux artifacts*, restated in full, because `archive-rar` is now a pass-through to `subx-core/archive-rar` and a core-side change to that gate would silently ship Linux binaries without `.rar` support. Artifact matrix, asset naming, smoke tests and every installer requirement are unchanged and untouched.
- `supply-chain-hardening`: **ADDS** two requirements — *Submodule Pointer Is a Supply-Chain Input*, making the pinned commit subject to the same freshness, provenance and review expectations as a version requirement (tracked branch recorded, automated update proposals, version agreement asserted, ancestry asserted, never bypassed with `--allow-dirty`); and *Each Published Crate Is Audited in Its Own Repository*, because the workspace lockfile the parent audits is a union that no consumer of `subx-core` alone ever resolves. **MODIFIES** *CI cargo audit gate*, restated in full from the text A0 leaves behind, so the audited surface is defined over the workspace lockfile with the submodule present, and so a second lockfile in a second repository is in scope rather than invisible.
- `crate-topology`: **MODIFIES** *Configuration Duplicated into the Core Repository*, restated in full, dropping the `.llvm-cov.toml` bullet — B1 duplicated it "for parity" and explicitly left the decision here, and this change deletes both copies — and adding `.github/workflows/` and `scripts/quality_check.sh` to the list, since a submodule inherits neither. **ADDS** *The Core Repository Has Its Own CI*, specifying what core's workflow runs, the two places it deliberately diverges from the parent's, and the rule that it never becomes a second publish path.

## Impact

- **Code:** No `.rs` file in either repository changes. `Cargo.toml`: `version` 1.9.1 → 2.0.0, and `default-members = [".", "subx-core"]` added to the `[workspace]` table. `Cargo.lock` regenerated. `.config/nextest.toml` in both repositories: junit path repaired and table relocated, comments translated in the parent's copy. `.llvm-cov.toml` **deleted** in both repositories. `.gitignore:19-20` collapsed to one pattern in both.
- **Scripts:** `scripts/quality_check.sh` and `scripts/quality_check.ps1` gain `--workspace` on four invocations each. `scripts/check_coverage.sh` and `scripts/check_coverage.ps1` gain `--ignore-filename-regex` on both report invocations, two new threshold variables with flags, a per-crate partition of the JSON summary, and a three-line verdict. A new, deliberately small `subx-core/scripts/quality_check.sh` is created — a dozen lines running the six cargo commands, called by core's own workflow so there is one definition rather than two. `scripts/install.sh` is not touched.
- **CI:** `build-test-audit-coverage.yml` — `--workspace` added at `:61`, `:133` and `:139`; four cache keys narrowed; three coverage threshold variables at `:186-198`; one new `submodule-pointer` job. `release.yml` — `publish-crates` rebuilt from one step into six. New `.github/dependabot.yml`. New `subx-core/.github/workflows/build-test-audit-coverage.yml`. All seven of B1's `submodules: recursive` lines and both `fetch-depth: 0` lines are preserved unchanged.
- **Tests:** None added, removed or modified. The 123 live test files are the ones B3 and B4 left; what changes is that `--workspace` makes all of them actually run under the gate, where 43 of them were being skipped.
- **APIs:** None. No public item in either crate is added, removed or changed.
- **Dependencies:** None added or removed. The resolved graph is unchanged; only which lockfiles are audited, and by whom, changes.
- **Documentation:** `AGENTS.md` — the `--workspace` requirement, the three coverage floors replacing `:47`'s bare "75%", and the two-crate publish flow in the CI/CD section; the stale "7 targets" claim at `:396-403` is left for C3. `subx-core/AGENTS.md` gains its CI and quality-script section. `docs/tech-architecture.md`'s CI paragraph. `CHANGELOG.md` gains the `## [2.0.0]` release section; `subx-core/CHANGELOG.md` is created with `## [1.0.0]`.
- **Coverage:** the instrumented run is unchanged — one `--workspace` pass over the same lines. What changes is the report: three gated numbers instead of one, an exclusion set that is actually applied for the first time, and a `subx-core` coverage figure published from core's own repository that is deliberately ungated because it is measured over a smaller numerator.
