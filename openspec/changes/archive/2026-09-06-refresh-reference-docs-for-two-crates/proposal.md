## Why

C3 (`refresh-docs-for-two-crate-architecture`) measured the documentation surface at 17.5 h against a ~9.5 h workday, drew the seam between **contract** documents and **reference** documents, and kept the first half. This change is the second half, named by C3's Decision 8 and booked in SDR §12 at 6.75 h.

C3's half was urgent because a wrong `AGENTS.md` produces wrong *work*: `AGENTS.md:18` instructs an agent to trust the file over the codebase, so a stale module guide puts a new file in the wrong git repository. This half is not urgent in that sense and is larger in every other. Three documents remain, and each is wrong in a way that a re-path cannot fix:

**1. `docs/tech-architecture.md` (651 lines, 23 KB) has module paths for headings.** `### CLI Layer (`src/cli/` and `src/commands/`)` at `:39`, `### Configuration Module (`src/config/`)` at `:73`, `### Core Engine (`src/core/`)` at `:118`, `#### Factory and Dependency Injection (`src/core/factory.rs`)` at `:120`, and nine more. After B2, four of those top-level sections describe the *other repository*, and the document's organising principle — "here are the layers of the crate" — no longer describes anything that exists. Its twenty-two `src/` citations are the smallest part of the problem; the structure is the problem.

It also carries defects that predate the series and that C3 catalogued rather than fixed:

| Location | Defect |
|---|---|
| `:51-60` | The `Commands` enum lists **seven** variants. `src/cli/mod.rs` has **eight** — `Translate(TranslateArgs)` (`:123`) is missing, although `docs/command-reference.md:3` correctly says "eight subcommands". |
| `:70` | Names `dialoguer` as a CLI-layer dependency "for interactive prompts". `dialoguer` is in no manifest. |
| `:144-147`, `:267-283` | Claims **three** AI provider implementations. There are **four**: `LocalLLMClient` is constructed at `src/core/factory.rs:232-234`. |
| `:298` | Providers "call `display_ai_usage` (from `src/cli/`)". A1 replaced that with `Reporter::ai_usage`; the named symbol no longer exists in core's reach. |
| `:509-591` | The hand-maintained dependency block. C3's Decision 6 resolves it; this change executes. |
| `:634-637` | "cross-compiles for four targets". `AGENTS.md` claimed seven and C3 fixed it to five. This file's independently-wrong number survives. |
| `:648` | "SubX runs on Linux (x86_64), Windows (x86_64), and macOS (x86_64, ARM64)" — `aarch64-unknown-linux-gnu` has been a published target since v1.6.0. |

**2. `docs/ai-provider-integration-guide.md` (574 lines, 21 KB) is a twelve-step procedure whose steps now land in two repositories.** Ten of the twelve name a file that moved to `subx-core` (Steps 1–8 and 10, at `:34`, `:114`, `:125`, `:147`, `:194`, `:231`, `:251`, `:272`, `:312`); Step 9 (`:305`, `src/cli/config_args.rs`) stays in `subx-cli`; Step 11 (`:319`) creates an integration test that lands in `subx-core/tests/` under B3's ownership rule; Step 12 (`:347-355`) edits `subx-cli`'s `docs/` and both READMEs. Its `## File Change Summary` table (`:496-516`) is fourteen rows of unqualified paths, offered explicitly as "a checklist before opening a pull request" — a checklist that now sends the reader to eleven paths that do not exist where it says they do. `:20-28` repeats the three-providers error while the file's own `## Local / OpenAI-Compatible Runtimes` section (`:374-495`) documents the fourth at length, and `:108` and `:563` both still instruct the author to call `display_ai_usage`.

**3. `docs/config-usage-analysis.md` (119 lines, 21 KB) is a dated snapshot pretending to be current.** Its footer reads `**最後更新**：2025-07-07`; the tree is at v1.9.1. It is the only zh-TW document under `docs/`, carries 33 line-precise `file.rs:line` citations that were stale before this series began, omits the entire `[translation]` configuration section that `docs/configuration-guide.md:226` documents, and contradicts itself — its summary states `vad.chunk_size` was "removed as non-existent" while its consistency section lists that same key as supported by both `get_config_value` and `set_config_value`. The split adds a second layer of wrongness on top: every `src/config/`, `src/core/` and `src/services/` citation now names the wrong repository. C3's Decision 10 resolves it; this change executes.

And there is one obligation C3 created that only this change can honour. C3 authored `subx-core/README.md` with **absolute** links into `subx-cli/docs/` — necessarily absolute, because a relative path across a submodule boundary resolves on neither the git forge nor docs.rs. This change re-authors two of the documents those links point into. Nothing in either repository's CI checks a cross-repository link: `subx-core`'s own workflow cannot see the parent's `docs/`, and the parent's workflow does not parse core's README. A section rename here silently breaks a link there.

## What Changes

**1. `docs/tech-architecture.md` is restructured around two crates rather than five layers.** `## Core Modules` (`:37`) becomes two sibling sections — one per crate — and every heading that is a module path is qualified with its repository. The document gains what the series produced and it never received: the `Reporter` seam as a first-class subsection (A1), `core::input` (A2), and the presentation split of `error.rs` (A2). Its `## Testing Strategy` (`:592-609`), `### CI/CD Pipeline` (`:624-637`), `### Distribution` (`:639-644`) and `## System Requirements` (`:646-651`) are re-scoped for two crates, two workflows, three coverage floors and five release targets. The seven pre-existing defects tabulated above are fixed in passing, because each one is a false statement in a section this change is rewriting anyway.

**2. The hand-maintained dependency block (`:509-591`) is deleted, executing C3's Decision 6.** What replaces it is the allocation *rule* — that `clap`, `clap_complete`, `colored`, `tabled` and `indicatif` are permanently `subx-cli`-only under SDR D8 and that a change placing any of them in core is a design error rather than a dependency addition; that `archive-rar` and `slow-tests` are owned in core and pass through from the CLI; that the audio, VAD and archive stack is core's — plus a pointer to the two manifests as the source of truth and the one command that answers the question the block was trying to answer (`cargo tree -p subx-core --depth 1`). A prose transcription of version numbers answers nothing a machine-readable file two directories away does not answer better; the rule is the only durable content and it is the part no manifest can express.

**3. `docs/ai-provider-integration-guide.md` is crate-qualified and stays one document.** It is **not** split into a core-side and a CLI-side guide, despite ten of twelve steps being core-side: it is a procedure that spans both repositories, and C3's Decision 3 established that such a document belongs where the work is coordinated, which is the superproject. Instead each step's `**File:**` line and every row of the `## File Change Summary` table names its repository, the table gains a **Repo** column, Step 11 states that the integration test lands in `subx-core/tests/` and why, the three-providers error at `:20-28` becomes four, and the two `display_ai_usage` instructions (`:108`, `:563`) become `Reporter::ai_usage` with a pointer to the seam A1 created.

**4. `docs/config-usage-analysis.md` is demoted to a dated record, executing C3's Decision 10.** It gains a header stating the commit it describes, that its call-site line numbers are a historical record and are not maintained, and that the current sources of truth are `docs/configuration-guide.md` for behaviour and `subx-core/src/config/` for implementation. Its path prefixes are re-qualified so the file at least names the correct repository. It is not deleted: its seven-key deprecated-configuration inventory is recorded nowhere else in either repository, and demoting it loses only a claim to freshness the file has not honoured in over a year.

**5. C3's Open Question 4 is resolved: the `update-config-document` skill survives, with its instructions changed.** C3 already corrected the skill's declared source-of-truth path (`src/config/` → `subx-core/src/config/`), because that was wrong the moment B2 landed. This change is the one that reads the skill and its primary document together, so it removes the skill's instruction to refresh call-hierarchy line numbers — an instruction that, against a demoted historical record, would undo the demotion on its next invocation — and re-points its purpose at the coverage matrix, which is the document's durable content.

**6. The cross-repository links C3 created are re-verified.** Every absolute URL in `subx-core/README.md` that targets `subx-cli/docs/` is resolved against the post-change documents, including anchors, and any that this change's restructuring invalidated is corrected — in `subx-core`, which is where the link lives.

**7. The acceptance condition is mechanical.** `grep -rn 'src/' docs/` yields no unqualified path: every hit reads either `subx-cli/src/…` or `subx-core/src/…`. C3 set this condition; this change is the one that satisfies it.

No CLI flag, configuration key, JSON envelope field, error variant, exit code, public API, manifest entry or script changes. This change touches three files under `docs/`, one skill, one changelog and one file in `subx-core`.

## Capabilities

### New Capabilities

_None._

### Modified Capabilities

- `release-distribution`: **ADDS** *Reference Documentation Is Crate-Qualified and Singly-Homed*, because the reference documents are the last place in the project where a source path may name no repository, and because two of them state a rule about their own maintenance that this change is fixing — a document that hand-transcribes a machine-readable file, and a document that is a dated snapshot presented as current. Neither obligation exists anywhere in the specification today. **MODIFIES** *Release documentation*, restated in full on C3's end state and carrying every one of C3's scenarios verbatim, to add the two obligations C3 cannot discharge alone. First, a cross-repository documentation link is a two-way commitment, and the change that re-authors the *target* is the change that must re-verify it, because neither repository's continuous integration can see both ends. Second, C3's clause binding user-facing documents to the published matrix reaches documents that name an **asset** or an **installer flag** — which is exactly what C3 repairs in `docs/command-reference.md` — and does not reach a document that merely states the matrix's *size*. `docs/tech-architecture.md:634-637` says "four targets" and names four triples; it names no asset and no flag, so C3's clause leaves it untouched and only this change fixes it. The clause is therefore widened here rather than dropped, and the widening is deliberately the half C3 could not satisfy. C1's two added requirements and C3's *Published Crate Documentation Sites* are untouched, as are every artifact-matrix, asset-naming, smoke-test and installer requirement.

## Impact

- **Code:** None. No `.rs` file, no manifest, no workflow and no script is touched. C3 owns the two edits in that class — narrowing `subx-core`'s `[package.metadata.docs.rs]` and the D11 re-export prose — and `design.md` Decision 1 records why they stay there.
- **Tests:** None. The acceptance condition is a `grep` over `docs/`, run as task 8.1; the cross-repository link check is task 6.2. Neither is a `#[test]`, for the reason C3's Decision 7 gives: a check whose subject is repository state belongs in the gate or in a task, not in the test binary. Unlike C3, this change adds nothing to `scripts/quality_check.sh` — a grep asserting that no document contains a bare `src/` path would fire on every legitimate future mention of a path inside a code block, and the false-positive rate is what would get it deleted.
- **APIs:** None.
- **Dependencies:** None.
- **Documentation:** `docs/tech-architecture.md` (restructured; `:37`, `:39`, `:51-60`, `:70`, `:73`, `:118-263`, `:144-147`, `:265-326`, `:298`, `:509-591` deleted, `:592-609`, `:624-637`, `:639-644`, `:646-651`); `docs/ai-provider-integration-guide.md` (`:20-28`, twelve `**File:**` lines, `:108`, `:319`, `:347-355`, `:496-516`, `:526`, `:557`, `:563`); `docs/config-usage-analysis.md` (header, footer, 33 path citations); `.github/skills/update-config-document/SKILL.md` (its line-number instruction and its statement of purpose — the path correction was C3's); `subx-core/README.md` (only the absolute links this change's restructuring invalidated); `CHANGELOG.md` gains a `### Documentation` entry under `[Unreleased]`, not under `## [2.0.0]` — see below.
- **Changelog placement:** this change lands after the 2.0.0 release section C1 authored and C3 completed, so its entry goes under `[Unreleased]`. It SHALL NOT be appended to `## [2.0.0]`, whose notes have by then been extracted into a published GitHub Release and cannot be amended retroactively. `subx-core/CHANGELOG.md` gains an entry only if task 6.2 finds a link to correct.
- **Sizing:** measured at 6.75 h, itemised in `design.md` Decision 8, with ~1.5 h of headroom against a ~9.5 h workday. The headroom is deliberate and its intended use is named: it is where re-deriving `config-usage-analysis.md`'s 33 call trees would go if the demotion reads badly once written.
