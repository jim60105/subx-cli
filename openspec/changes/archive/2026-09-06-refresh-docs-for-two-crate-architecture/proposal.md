## Why

Ten changes have landed a two-repository, two-crate architecture and each of them deferred its documentation debt here. The debt is not a tidy-up backlog: every document that tells a contributor or an agent *where code lives* is now actively misleading, and the documents that are misleading are the ones read **before** work starts.

`AGENTS.md` is the sharpest case. Its "Layer Overview" (`:87-93`) prints five layers all rooted at `src/`, its "Module Guide" (`:112-131`) places `config/`, `core/`, `services/` and `error.rs` under `src/`, and its "File Organization" tree (`:145-181`) shows one `src/` and one `tests/`. After B2 and B3 every one of those rows names a path in the *other repository*. An agent that trusts the file — which line 18 explicitly instructs it to do ("Trust these instructions — only search the codebase if they are incomplete or produce errors") — will create a file in the wrong crate, and the wrong crate is a different git repository with a different publish lifecycle. The instruction to trust the file is what makes its staleness expensive rather than merely untidy.

`subx-core` has the mirror problem. B1 shipped a first-cut `AGENTS.md` derived from the parent's; B2, B3, B4, C1 and C2a each added a section to it as a side effect of their own work, and C2a explicitly recorded that it "writes the paragraph into `subx-cli`'s and hands the core copy forward" rather than authoring core's file. Nobody owns the result. A contributor in a standalone `subx-core` clone — the only way the Tauri GUI at `../subx` and every crates.io consumer will ever see the crate — reads an accreted document that no change has ever read end to end.

Three further classes of debt were named by siblings and left here explicitly:

| Left by | What |
|---|---|
| A0 | `docs/tech-architecture.md:511-591` hand-mirrors `Cargo.toml`. A0 re-syncs it once more; it has now drifted at least ten ways (five dead crates, `dialoguer` and `md5` which are in no manifest, `tokio` as `"full"`, `symphonia` as `"all"`, `rubato` at `0.16.2` against a real `2.0`, `hound` in the wrong section, and eight archive/audio dependencies missing entirely). |
| A1, A2 | The `Reporter` seam and the `core::input` / `SubXErrorExt` split. `docs/ai-provider-integration-guide.md:563` still instructs a new-provider author to "Call `display_ai_usage`"; `docs/machine-readable-output.md:864-865` still puts `exit_code` and `user_friendly_message` in `error.rs`. |
| B1, B3, B4, C1, C2a, C2b | The submodule contract, the module ownership boundary, the "which crate does my test belong to" rule, the `test-support` mechanism, the `CARGO_BIN_EXE_subx-cli` contract, the three coverage floors, the two-crate publish flow and the `spec-governance` rules — each written into one file by the change that created it, none reconciled with the others. C2a and C2b additionally left the `spec-governance` **drift check** unimplemented, on the grounds that its natural home is a script this change is already opening. |
| C1 | `AGENTS.md`'s release paragraph (`:395-402`, cited by C1 as `:396-403`) claims **7** release targets. The real matrix is **5**; musl was deliberately dropped in `2026-04-28-drop-musl-support`. C1's task 10.3 leaves it here, as B1's task 8.3 arranged. |

And the split is not the only source of wrongness. Two defects predate the series and are provable, not stylistic:

- **`docs/command-reference.md:16-40` still documents four musl assets and tells users to opt in with `SUBX_LIBC=musl` or `--musl`.** The installer's *only* legal handling of those two inputs is to exit `2` without a network call (`release-distribution` § *Installer musl-input rejection*). The user-facing command reference instructs users to do the one thing the specification requires to fail. That is a documented lie in the most-read reference document, and it has survived since v1.7.2.
- **`AGENTS.md:137`** points the "Add/change CLI arguments" row at `src/cli/validation.rs`, a 0-byte orphan A0 deletes, and its `docs/` inventory (`:151-156`) omits `docs/machine-readable-output.md` entirely — 867 lines, 31 KB, the largest document in the tree.

The surface is 4,292 lines and 178 KB across nine `subx-cli` documents, plus `CHANGELOG.md` (552 lines), plus three new or first-cut documents in `subx-core`. That does not fit one workday, and this change says so up front and names its seam rather than overflowing silently (`design.md` Decision 8).

## What Changes

**1. `AGENTS.md` (`subx-cli`) is rewritten for two crates and its pre-existing defects are fixed.** Nine sections are re-scoped: "Execution Flow" (`:76-83`) and "Layer Overview" (`:85-93`) gain the crate boundary; "Module Guide" (`:112-131`) gains a **Crate** column; "Common Edit Targets" (`:133-143`) gains crate-qualified paths and loses the `src/cli/validation.rs` reference (`:137`); "File Organization" (`:145-181`) becomes a two-repository tree and its `docs/` inventory gains the missing `machine-readable-output.md`; "Cargo Features" (`:183-189`) states which manifest owns each gate and which is a pass-through; "Error Handling" (`:206-211`) splits `exit_code()`/`user_friendly_message()` from the core enum; "CI/CD Pipeline" (`:387-402`) drops the stale "7 targets" claim (`:395-402`) for the real five; and "Documentation Conventions" (`:290-298`) gains the cross-crate intra-doc link rule. The `<!-- CODEGRAPH_START -->…<!-- CODEGRAPH_END -->` block (`:412-421`) is preserved byte-for-byte — it is tool-managed and this change does not author it.

**2. `subx-core/AGENTS.md` is authored, not accreted.** It is read end to end and made correct as a *library* document: no execution flow through `main.rs`, no CLI layer, no release matrix, no shell completions, no installer. It gains what the accretion left half-stated — the module guide for `core/`, `services/`, `config/`, `error.rs` and `report/`, the rule that core may never name `subx-cli` in code or in an intra-doc link, the `test-support` mechanism from core's side, the local `scripts/quality_check.sh` C1 created and its relationship to the authoritative parent gate, and the `openspec/` two-root rule C2a handed forward.

**3. The two `AGENTS.md` files share a marked, mechanically-checked region.** The conventions that are genuinely identical — coding rules, testing critical rules, documentation conventions, the changelog convention, the CPU-intensive-operations warning — are enclosed in `<!-- SHARED_CONVENTIONS_START -->` / `<!-- SHARED_CONVENTIONS_END -->` markers in both files, reusing the marker convention the repository already uses for CodeGraph. Everything outside the markers is per-repository by design. See `design.md` Decision 1.

**4. The `spec-governance` drift check becomes running code, and it carries the AGENTS.md check with it.** C2a specified it, C2b built the record it reads (`openspec/split-capabilities.txt`), and both deferred placement here. It lands as a function in `subx-cli/scripts/quality_check.sh` with a PowerShell counterpart in `quality_check.ps1`, asserting three predicates: no capability directory name appears in both `openspec/specs/` trees unless it is recorded in `split-capabilities.txt`; every name in `split-capabilities.txt` is present in **both** trees (a split that lost a half); and the marked shared region of the two `AGENTS.md` files is byte-identical. It runs only in the superproject, because only the superproject can see both trees.

**5. Both READMEs are re-scoped for two published crates and two doc sites.** The badge row gains a `docs.rs/subx-core` badge; the "From Source" block gains `--recurse-submodules`; a new short section states that `cargo install subx-cli` is the CLI install path and `subx-core = "1"` is the library dependency, and that a library consumer should depend on `subx-core` and never on `subx-cli`. `README.zh-TW.md` mirrors every change. The relative `assets/logo.svg` reference (`README.md:4`) is verified against crates.io's rendering and made absolute if it does not resolve.

**6. `subx-core/README.md` is authored as an API-consumer document, deliberately not a copy of the CLI's.** No logo (it lives in `subx-cli/assets/`, which `Cargo.toml:19` excludes from the package), no install story, no command table, no `subx-cli` workflow badges — core has its own workflow after C1. It carries: what the crate is, its two consumers, that a standalone clone is the supported way to depend on it, the `test-support` and `archive-rar` features, the caret relationship to `subx-cli`, and a link to `docs.rs/subx-core`. Links back into `subx-cli/docs/` are **absolute** URLs, because a relative path across a submodule boundary resolves on neither GitHub nor docs.rs.

**7. `CHANGELOG.md` gains the `### Documentation` entry under the `## [2.0.0]` section C1 created**, and `subx-core/CHANGELOG.md` gains its own. Neither header is touched: `release.yml:29`'s `awk` extraction depends on the exact `## [<version>]` shape and C1 owns it.

**8. Three `docs/` files are corrected here because their defects are provable and their edits are mechanical**: `docs/command-reference.md`'s musl table and opt-in instructions (`:10-40`), which contradict a normative requirement; `docs/machine-readable-output.md`'s four source paths (`:639`, `:748`, `:863`, `:864-865`) and its `## References` pointer to an unarchived change directory that has been `openspec/changes/archive/2026-04-26-add-machine-readable-output/` since April; and `docs/configuration-guide.md`'s single path (`:341`) and its "5 places" checklist.

**9. `docs/tech-architecture.md`, `docs/ai-provider-integration-guide.md` and `docs/config-usage-analysis.md` are out of scope and belong to C4**, `refresh-reference-docs-for-two-crates`, which exists and is sequenced immediately after this change (SDR §12). They are the three documents whose repair is a re-authoring rather than a re-path: 651 lines whose headings are literally module paths, 574 lines with 37 touchpoints across a 12-step procedure that now spans two repositories, and a dated zh-TW snapshot with 33 line-precise citations that were stale before this series began. C4 blocks nothing — D1 and D2 read no documentation. This change makes two decisions that C4 executes (`design.md` Decisions 6 and 10) so that C4 inherits no open design, and touches none of the three files, so that C4's own baseline read is reliable. `design.md` Decision 8 carries this change's measurement and the reason the seam falls where it does; C4's `design.md` Decision 8 re-derives its own.

No CLI flag, configuration key, JSON envelope field, error variant, exit code or public API changes. One task touches a manifest: `subx-core`'s `[package.metadata.docs.rs] all-features = true`, which B1 duplicated from the parent and which now activates the `test-support` feature on the public doc site, publishing test scaffolding as part of the crate's documented surface (`design.md` Decision 5).

## Capabilities

### New Capabilities

_None._

### Modified Capabilities

- `release-distribution`: **ADDS** *Published Crate Documentation Sites*, because docs.rs is a distribution channel for the published artifacts and the split turns one doc site into two with a resolution asymmetry between them — `subx-cli` may link into `subx_core` because it is a dependency, `subx-core` may never link into `subx_cli` because it is not, and under `broken_intra_doc_links = "deny"` the second is a hard build failure in the repository least able to detect it. The requirement also fixes that the boundary is verified by a doc build **with** dependencies, since a `--no-deps` build satisfies the lint while producing dead cross-crate hrefs. **MODIFIES** *Release documentation*, restated in full, because the documented install story now has two shapes (a binary/`cargo install` path for the CLI, a crate-dependency path for the library) and a from-source path that fails without `--recurse-submodules`; and *Changelog entry for new artifacts*, restated in full, because the changelog obligation now spans two files in two repositories with independent version lines. Every artifact-matrix, asset-naming, smoke-test and installer requirement is unchanged and untouched, as are C1's two added requirements.

## Impact

- **Code:** `scripts/quality_check.sh` and `scripts/quality_check.ps1` gain the three-predicate governance check as a new step. `subx-core/Cargo.toml`'s `[package.metadata.docs.rs]` block is narrowed, or `subx-core/src/test_support/mod.rs` gains `#[doc(hidden)]` — one of the two, decided in `design.md` Decision 5. No other source file changes; no `src/` module in either crate is added, removed or renamed.
- **Tests:** None as new test functions. The governance check is a script assertion, not a `#[test]`, because it reads two `openspec/` trees and two `AGENTS.md` files rather than any Rust symbol — the same reasoning C1 used for its `--allow-dirty` grep assertion. It is exercised by running `scripts/quality_check.sh` on a deliberately-broken fixture state and confirming a red verdict before the real run (tasks 4.5–4.7).
- **APIs:** None. If Decision 5 resolves to `#[doc(hidden)]`, `subx_core::test_support::*` remains callable and merely stops appearing on the doc site; SDR D10's guarantee that the test utilities are unconditional public API is unaffected either way.
- **Dependencies:** None added or removed. If Decision 5 resolves by narrowing `[package.metadata.docs.rs]`, the docs.rs build stops activating `test-support` and therefore stops pulling `wiremock` and `hound` into the documentation build; no manifest dependency entry changes.
- **Documentation:** `AGENTS.md` (nine sections re-scoped, `:137`, `:151-156` and `:395-402` repaired, `:412-421` preserved verbatim); `subx-core/AGENTS.md` (authored end to end); `README.md` and `README.zh-TW.md` (badge row, from-source block, a new two-crate consumption section); `subx-core/README.md` (authored); `docs/command-reference.md:10-40`; `docs/machine-readable-output.md:639,748,863-865` and its `## References` block; `docs/configuration-guide.md:341` and its adding-keys checklist; `.github/skills/update-config-document/SKILL.md`, whose declared source of truth `src/config/` moved repositories in B2 and which no sibling change claimed. `CHANGELOG.md` gains `### Documentation` under `## [2.0.0]`; `subx-core/CHANGELOG.md` gains the same under its `## [1.0.0]`. `docs/tech-architecture.md`, `docs/ai-provider-integration-guide.md` and `docs/config-usage-analysis.md` are **not** touched here and are C4's entire scope.
- **Sizing and seam:** measured at **10.75 h** against a ~9.5 h effective workday (C1's own accepted figure) — ~1.25 h over, stated rather than absorbed, with the relief valve named in `design.md` Decision 8: the 1.5 h small-corrections row (tasks 6.1–6.8) moves to C4 if task 2 exceeds 3 h. C4, `refresh-reference-docs-for-two-crates`, holds the remaining **6.75 h** and is authored rather than merely named. The two sum to the 17.5 h originally measured. **SDR §12 currently records 9.25 h for this change; that figure came from an arithmetic slip in an earlier draft and needs correcting to 10.75 h.**
