## Why

SDR §8 records six API gaps that force the downstream Tauri GUI (`../subx`) to duplicate logic that `subx-core` already owns. This change closes **gaps 1 and 2**; D2 (`expose-core-orchestration-apis`) closes gaps 3–6. Neither blocks anything in the split: SDR D9 puts both off the critical path.

**Gap 1 — the format-driving engines are neither `Send` nor `Sync`.** `FormatManager` holds `Vec<Box<dyn SubtitleFormat>>` (`src/core/formats/manager.rs:23`). `dyn SubtitleFormat` erases auto traits, so the vector is neither `Send` nor `Sync`, and the property propagates to the two types that embed a `FormatManager` by value: `FormatConverter` (`converter.rs:29`) and `TranslationEngine` (`translation/engine.rs:36`). Tauri requires an async command's future to be `Send`, and `tauri::State<T>` requires `T: Send + Sync + 'static`. So the GUI cannot hold any of the three across an `.await` and cannot put one in shared state. Its workaround is `tokio::task::spawn_blocking` plus a **private current-thread runtime built inside the worker** in two command modules (`convert.rs:394-423`, `translate.rs:459-555`), and defensive scoping in two more places (`translate.rs:193-195`, `:284-288`, `sync.rs:336-347`) whose only job is to guarantee a `FormatManager` is dropped before the next `.await`. Five separate comments in that repository exist to explain a constraint that has no reason to exist.

**Gap 2 — `SyncEngine::new` refuses to construct for callers that only want `apply_manual_offset`.** `SyncEngine::new` (`src/core/sync/engine.rs:36-68`) returns `Err(SubXError::config("VAD detector is required but not available"))` whenever it ends up without a detector — and that includes the branch where the *configuration* disabled VAD (`:37`, `:51-61`). `apply_manual_offset` (`:148-204`) touches neither the detector nor the audio pipeline; it is a pure timing transform over `Subtitle`. Because it is reachable only through a constructed engine, the GUI reimplements it as `shift_subtitle` (`../subx/src-tauri/src/commands/sync.rs:278-300`) and carries two drift-guard tests (`:604-630`) plus a module-doc paragraph (`:13-17`) to keep the copy honest.

Both gaps have the same shape: a library capability that is correct, tested and already public is unreachable from an async, multi-threaded host because of an incidental property of how it is stored or constructed. Closing them deletes ~150 lines of duplicated and defensive code from the GUI and removes the last two reasons that repository has to reason about `subx-core`'s internals.

## What Changes

**1. `SubtitleFormat` gains `Send + Sync` supertraits.** `pub trait SubtitleFormat` becomes `pub trait SubtitleFormat: Send + Sync` (`subx-core/src/core/formats/types.rs:835`). Every field type, method signature, return type and public path is unchanged; `Box<dyn SubtitleFormat>`, `&dyn SubtitleFormat` and the two `Option<&dyn SubtitleFormat>` accessors (`manager.rs:59`, `:68`) are written exactly as they are today and simply become thread-safe. All four implementors — `AssFormat`, `VttFormat`, `SrtFormat`, `SubFormat` — are unit structs (`ass/mod.rs:99`, `vtt/mod.rs:35`, `srt/mod.rs:25`, `sub/mod.rs:35`) and satisfy the bound with no edit. `FormatManager`, `FormatConverter` and `TranslationEngine` then become `Send + Sync` with no change to their own definitions, because `AIProvider` (`services/ai/mod.rs:153`) and `ConfigService` (`config/service.rs:61`) already carry the bounds and every other field is plain data.

**2. The guarantee is locked by compile-time assertions, not by prose.** A new private `thread_safety` test module in `subx-core/src/core/mod.rs` instantiates `const fn assert_send_sync<T: Send + Sync + 'static>()` over `FormatManager`, `FormatConverter`, `TranslationEngine`, `MatchEngine`, `SyncEngine`, `ComponentFactory`, `FileManager` and `Box<dyn SubtitleFormat>`. The four types that are already `Send + Sync` today are included deliberately: the assertion set is the contract, and a type entering it later must be added by the change that adds it.

**3. `subx_core::core::sync::shift_subtitle_timing` is added.** A free function in `subx-core/src/core/sync/mod.rs`, alongside A2's `resolve_sync_pairing` and `create_default_output_path`:

```rust
pub fn shift_subtitle_timing(subtitle: &mut Subtitle, offset_seconds: f32) -> Result<SyncResult>;
```

It holds the entire body of today's `apply_manual_offset` **except** the `sync.max_offset_seconds` guard: the positive-offset `checked_add` overflow error, the negative-offset clamp to `Duration::ZERO`, and the `SyncResult { method_used: SyncMethod::Manual, confidence: 1.0, correlation_peak: 1.0, additional_info: … }` construction, byte for byte. `SyncEngine::apply_manual_offset` is rewritten to the clamp check followed by `shift_subtitle_timing(subtitle, offset_seconds)`, so there is exactly one implementation of the shift and the CLI's observable behaviour is unchanged.

**4. Nothing else moves.** `SyncEngine::new` keeps its signature *and* its behaviour, including the unconditional VAD requirement. No constructor signature changes anywhere (A1's locked constraint on `MatchEngine::new`, `SyncEngine::new`, `TranslationEngine::new` and `ComponentFactory::new` is respected without effort — none of them is touched). No public path is added, removed or reshaped, so B2's *Public API Path Stability for the Library Surface* requirement is unaffected.

**5. Sequencing is part of the change.** Adding a supertrait to a public trait is a major-version event for a published crate. This change therefore lands **after C1 and before C2a**, which is permitted by the plan (`tmp/split-implementation-plan.zh-TW.md` §2 records C1 and C2a/C2b as mutually independent) and makes the supertrait part of `subx-core`'s 1.0.0 surface rather than a break against it. `design.md` Decision 6 states the four prerequisites and what each buys; the plan's dependency table records only one of them.

## Capabilities

### New Capabilities

_None._

### Modified Capabilities

- `async-runtime-safety`: gains one requirement, *Library Engine Types Are `Send` and `Sync`*, naming the eight types that must satisfy the bound, the compile-time assertion that enforces it, and the rule that removing the bound is a breaking change. This capability moves wholesale to `subx-core` in C2a (SDR §9), and its purpose — "protect the tokio runtime … ensure scheduler state remains consistent" — already covers what a library type must be for a multi-threaded runtime to hold it.
- `format-conversion`: *Public format API stability across module reorganization* is modified. It is the requirement that enumerates `SubtitleFormat`'s public surface and freezes its method signatures; the supertrait list is part of that surface, and the requirement is where an implementor learns what it must satisfy. Classified **core** by C2b (`design.md` Decision 2, `format-conversion` table).
- `timeline-sync`: gains *VAD-Independent Manual Offset Application* and modifies *Sync Method Selection*, *Offset Clamping Against Maximum* and *Subtitle Timing Application*. The first is the new entry point; the other three are the requirements that currently locate the shift semantics and the offset guard on `SyncEngine::apply_manual_offset`, and after this change the shift belongs to the free function while the guard stays on the method. All four are classified **core** by C2b.

## Impact

- **Code:** `subx-core/src/core/formats/types.rs` (`SubtitleFormat` supertraits, rustdoc, the `rust,ignore` implementor example), `subx-core/src/core/formats/manager.rs` (rustdoc only — no signature changes), `subx-core/src/core/sync/mod.rs` (`shift_subtitle_timing` and its module rustdoc), `subx-core/src/core/sync/engine.rs` (`apply_manual_offset` becomes guard + delegation), `subx-core/src/core/mod.rs` (the `thread_safety` assertion module). **No file in `subx-cli/src/` changes**; `subx_cli::core::formats::SubtitleFormat` reaches the trait through SDR D11's re-export and acquires the supertraits with it.
- **Tests:** the new `thread_safety` assertion module (compile-time only — it has no runtime body); new unit tests for `shift_subtitle_timing` in `subx-core/src/core/sync/mod.rs`'s test module covering the positive shift, the negative clamp at and past zero, the `Duration::MAX` overflow error, the empty-subtitle case, and that no `max_offset_seconds` guard fires; a delegation test asserting `SyncEngine::apply_manual_offset` and `shift_subtitle_timing` produce identical `SyncResult` fields and identical entry timings for the same input. The two existing `apply_manual_offset` tests (`engine.rs:357`, `:375`) stay exactly as they are — they are the regression check that the delegation did not change behaviour.
- **APIs:** **Additive:** `subx_core::core::sync::shift_subtitle_timing` (and `subx_cli::core::sync::shift_subtitle_timing` via the D11 re-export). **Breaking in the semver sense:** `SubtitleFormat` gains two supertraits, which `cargo-semver-checks` reports as `trait_added_supertrait` (major). No implementor exists outside `subx-core` — the GUI implements `AIProvider` in four test doubles (`../subx/src-tauri/src/commands/match.rs:592`, `:636`, `translate.rs:923`, `:1554`) and `SubtitleFormat` nowhere, and there are no implementors in `subx-cli/src/` or in either test suite. Landed before `subx-core` 1.0.0 and `subx-cli` 2.0.0 are published, the break has no audience and no version consequence; landed after, it forces `subx-core` 2.0.0. See `design.md` Decisions 5 and 6.
- **Dependencies:** None. No manifest in either repository changes.
- **Documentation:** `subx-core/src/core/formats/types.rs`'s trait rustdoc gains an `# Implementation Notes` clause stating the `Send + Sync` obligation, and its `rust,ignore` example gains a line noting `MyFormat` satisfies it; `subx-core/src/core/sync/mod.rs`'s module rustdoc lists `shift_subtitle_timing` in its `# Core Components` block with a `# Examples` block that compiles; `subx-core/CHANGELOG.md` gains `[Unreleased]` → `### Added` (the free function) and `### Changed` (the supertraits, with the semver note) entries — **`subx-core`'s CHANGELOG, not `subx-cli`'s**, because every source edit is in that repository; `subx-cli/CHANGELOG.md` gains one `### Changed` line under `[Unreleased]` recording that the re-exported trait's bounds changed, because `subx-cli`'s library surface is what an existing `subx_cli::` consumer sees. `docs/tech-architecture.md`'s format-system paragraph gains one sentence; the two-crate rewrite of that file remains C3's.
